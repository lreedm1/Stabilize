Privacy and memory

What the current prototype remembers

The native iOS app is guest-only and does not save a conversation transcript. Guest use on the website does not create server-side conversation memory. Signed-in web use can retain condensed context for continuity, subject to the limits below.

Native iOS app

The native app does not offer sign-in, retain cookies, or store a transcript on disk. The visible conversation remains in memory only while the app is open. Before the first send, the app asks for permission to send the message to stabilize.info and share it with OpenAI, a third-party AI provider, to generate an ordinary reply. Some urgent messages may receive a fixed response from the Stabilize server without an OpenAI request.

To stop future AI sharing, open About, find AI sharing permission, and choose Revoke AI Sharing Permission. The next attempted send will ask again. Revoking permission does not recall messages already sent or undo processing that has already occurred.

Guest use on the website

When you use the website without signing in, the application does not store a server-side conversation history for later sessions. To avoid losing the most recent result during ordinary navigation, the latest assistant reply and minimal display state are stored in session storage for the current browser tab for up to 24 hours. The user's prompt is not included in that tab-scoped record. It is cleared when the tab closes, when you sign out, or when the record expires. Your message still travels through Cloudflare infrastructure and, for ordinary AI replies, is processed by OpenAI.

Signed-in web memory

Google sign-in is optional on the website and is used only to associate a one-way account alias with a rolling summary and a small recent-message buffer. The current implementation is designed to delete that remembered context 30 days after the last stored exchange.

Public feedback

Signed-in web users can optionally submit feedback. Each accepted submission is committed as a separate JSON file on the public feedback-inbox branch of the Stabilize GitHub repository. The committed record contains the feedback text, category, submission time, a random feedback identifier, and a note that the submission came from Stabilize. It does not include the Google account alias, email address, IP address, browser user agent, chat history, or payment information. The one-way account alias is used temporarily in a separate Cloudflare Durable Object only to limit spam. Because the Git repository is public, feedback submitters are told not to include private or identifying information and must acknowledge that warning before submission.

Paid model choice on the website

If you subscribe to model choice, Stripe hosts checkout and the billing portal and processes payment information under Stripe's terms. Stabilize does not receive or store complete card numbers. It stores Stripe customer and subscription identifiers, subscription status, the chosen AI model, and a monthly paid-model message count under the same one-way account alias used for signed-in continuity. Billing records may remain longer than conversation memory because they are needed to provide and manage an active or historical subscription.

Network metadata and Worker telemetry

The application does not use IP addresses as conversation-memory identifiers and does not request a Google email address for account memory. The Stabilize release configuration disables Cloudflare Workers observability persistence, invocation logs, and traces and does not configure Logpush or telemetry export destinations. The application also avoids writing message text to its own logs. Cloudflare and other network infrastructure still necessarily process connection and request metadata to deliver and protect the service under their own terms.

Third-party processing

Cloudflare hosts the application and handles requests. Google handles optional website sign-in. GitHub stores optional public feedback. Stripe handles optional website checkout, subscription billing, and the customer billing portal. OpenAI processes messages used to generate ordinary replies and, for signed-in website use, condensed memory. The application requests that OpenAI not store Responses API objects by sending store: false, but provider processing still occurs and OpenAI may retain inputs and outputs in abuse-monitoring logs under the deployment's applicable data controls and terms.

Privacy and deletion requests

Contact info@reedlokken.com or visit the support page with privacy questions or deletion requests. Do not include chat text in the request. Because native and web guest chats are not assigned to a Stabilize account, support may be unable to identify a specific guest message. Requests can cover data Stabilize controls; processing already completed by a service provider remains subject to that provider's controls and terms.

Use caution with sensitive information

Do not enter passwords, authentication codes, financial account numbers, or information you do not want transmitted to the service providers involved. No internet service can promise zero risk.

Prototype status: This summary describes the intended release implementation. A broad production launch requires independent privacy, security, tax, payment, and legal review and verification that deployed provider settings match this page.
