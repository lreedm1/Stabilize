Privacy and memory

What the current prototype remembers

Guest messages do not enter server-side conversation memory. The current browser tab can temporarily keep the latest assistant reply so it can be restored after a refresh or a visit to another Stabilize page. Signed-in use can retain bounded context for continuity, subject to the limits below.

Guest use

When you use Stabilize without signing in, the application does not store server-side conversation history for later sessions. To avoid losing the most recent result during ordinary navigation, the latest assistant reply and minimal display state are stored in session storage for the current browser tab for up to 24 hours. The prompt itself is not included in that tab-scoped record, although an assistant reply can reflect information from it. The record expires after 24 hours and is cleared when you sign out; browsers normally discard session storage when a tab closes but may restore it as part of a saved browser session. Your message still travels through Cloudflare infrastructure and, for ordinary AI replies, is processed by OpenAI with store: false. Signing in later affects future messages only; earlier guest messages are not moved into account memory.

Signed-in memory

Google sign-in is optional and associates a one-way account alias with a bounded summary and recent-message buffer stored by Stabilize on Cloudflare. That remembered text expires 30 days after the last committed exchange. You can also delete it from the signed-in account menu; signing out alone does not delete it. Signed-in assistant replies are not placed in the browser's 24-hour latest-reply cache. After deletion succeeds, a signed, account-bound receipt cookie confirms the result on the next page and is then cleared; it contains no chat text. Cookies issued before the deletion are rejected from account features, so another browser or device using an older session must sign in again.

Public feedback

Signed-in users can optionally submit feedback. Each accepted submission is committed as a separate JSON file on the public feedback-inbox branch of the Stabilize GitHub repository. The committed record contains the feedback text, category, submission time, a random feedback identifier, and a note that the submission came from Stabilize. It does not include the Google account alias, email address, IP address, browser user agent, chat history, or payment information. Before a submission is accepted, the privacy-preserving account alias is temporarily used in a separate Durable Object to enforce the feedback rate limit; that rate-limit state is not included in the public feedback file. Because the Git repository is public, feedback submitters are told not to include private or identifying information and must acknowledge that warning before submission.

Paid model choice

If you subscribe to model choice, Stripe hosts checkout and the billing portal and processes payment information under Stripe's terms. Stabilize does not receive or store complete card numbers. It stores Stripe customer and subscription identifiers, subscription status, the chosen AI model, and a monthly paid-model message count under the same one-way account alias used for signed-in continuity. Billing records may remain longer than conversation memory because they are needed to provide and manage an active or historical subscription.

What is not used for memory

The application is not designed to use IP addresses as conversation-memory identifiers. It does not request your Google email for account memory. Infrastructure providers may still process network metadata under their own terms.

Third-party processing

Cloudflare hosts the application and handles requests. Google handles optional sign-in. GitHub stores optional public feedback. Stripe handles optional checkout, subscription billing, and the customer billing portal. OpenAI processes messages used to generate replies and condensed memory. Guest, summary, and signed-in reply requests use store: false. OpenAI is used for stateless processing, not as Stabilize's account-memory store. OpenAI may separately retain data in abuse-monitoring logs under the deployment's applicable data controls and terms.

Use caution with sensitive information

Do not enter passwords, authentication codes, financial account numbers, or information you do not want transmitted to the service providers involved. No internet service can promise zero risk.

Prototype status: This summary describes the intended current implementation. A production launch requires independent privacy, security, tax, payment, and legal review.
