Privacy and memory

What the current prototype remembers

Stabilize does not create its own server-side conversation history for guest chats. The current web tab temporarily keeps only the latest assistant reply, and the native iOS app does not intentionally save a prompt or reply on the device. OpenAI provider storage still applies as described below.

Guest web use

When you use Stabilize on the web without signing in, the application does not retain a server-side conversation history for later guest sessions. The latest assistant reply and minimal display state are stored in session storage for the current browser tab for up to 24 hours so a result can survive a refresh or ordinary navigation. The user's prompt is not included in that tab-scoped record. It is cleared when the tab closes, when you sign out, or when the record expires. Messages still travel through Cloudflare and, for ordinary AI replies, are processed and stored by OpenAI under the provider behavior below.

Native iOS app

Version 1 of the native iOS app is guest-only. Before its first send, the app explains that the message goes through Stabilize's Cloudflare Worker and, for an ordinary reply, is shared with OpenAI. Nothing is sent until the user allows that sharing. The permission choice is stored locally in app-specific settings and can be revoked under About, which makes the app ask again before a later send. Revoking permission cannot recall data already transmitted.

The native app does not intentionally persist the user's prompt or assistant reply, does not offer account sign-in, and does not create a retrievable guest conversation history on the Stabilize Worker. Some urgent messages may receive a fixed safety response without an OpenAI request. When the app leaves the foreground, it displays a privacy cover intended to obscure prompts and replies in the app switcher. iOS may still create ordinary system-level snapshots, logs, backups, or network records under Apple's platform behavior. The app does not add analytics, advertising, tracking, location, camera, microphone, contacts, HealthKit, or notification SDKs.

Signed-in web memory

Google sign-in is optional on the website and is used only to associate a one-way account alias with a rolling summary and a small recent-message buffer. The current implementation is designed to delete that remembered Stabilize context 30 days after the last stored exchange. This local retention limit does not shorten the separate OpenAI storage period.

Private chat

Signed-in users can start Private chat from the site menu. While it is active, the chat does not use or update your Stabilize memory: the Worker does not read your rolling summary or recent-message buffer, and it does not write the message, response, or a fixed safety-route event back to account memory. Starting another conversation while in Private chat also leaves the existing account memory unchanged.

The Private chat setting is kept only for the current browser tab so it can survive a refresh, and a visible label stays above the composer while it is active. Private chat is not a separate provider-retention mode. Cloudflare still carries the request, and OpenAI processing and storage still applies to ordinary AI replies as described below.

Public feedback

Signed-in web users can optionally submit feedback. Each accepted submission is committed as a separate JSON file on the public feedback-inbox branch of the Stabilize GitHub repository. The committed record contains the feedback text, category, submission time, a random feedback identifier, and a note that it came from Stabilize. It does not include the Google account alias, email address, IP address, browser user agent, chat history, or payment information. Because the repository is public, submitters are told not to include private or identifying information and must acknowledge that warning.

Paid model choice on the web

If you subscribe to model choice on the website, Stripe hosts checkout and the billing portal and processes payment information under Stripe's terms. Stabilize does not receive or store complete card numbers. It stores Stripe customer and subscription identifiers, subscription status, the chosen AI model, and a monthly paid-model message count under the same one-way account alias used for signed-in continuity. Billing records may remain longer than conversation memory because they are needed to manage an active or historical subscription. Version 1 of the native iOS app does not offer purchases or subscription management.

What is not used for memory

The application is not designed to use IP addresses as conversation-memory identifiers. It does not request your Google email for account memory. Infrastructure providers may still process network metadata under their own terms.

Third-party processing and retention

Cloudflare hosts the application and handles requests. Google handles optional web sign-in. GitHub stores optional public feedback. Stripe handles optional web checkout, subscription billing, and the customer billing portal. Apple distributes the native app and may process App Store, device, crash, and diagnostic information under Apple's terms and user settings.

OpenAI processes messages used to generate ordinary replies and condensed web memory. Stabilize sends both reply and summary requests with store: true. Under OpenAI's current platform documentation, resulting Responses API data is stored as application state for at least 30 days unless organization or project data controls cause the request to be treated differently. OpenAI says API data is not used to train its models unless the API customer explicitly opts in. Private chat prevents Stabilize account-memory reads and writes, but it does not change this provider processing.

Use caution with sensitive information

Do not enter passwords, authentication codes, financial account numbers, or information you do not want transmitted to the service providers involved. No internet service can promise zero risk.

Questions and deletion requests

See Support for contact information. Stabilize cannot identify a particular guest chat as an account history for deletion. Signed-in web requests can cover account-linked records controlled by Stabilize. A local deletion, Private chat setting, or consent revocation does not recall processing already completed by a provider or shorten OpenAI's stored Responses retention period.

Prototype status: This summary describes the intended current implementation. A production launch requires independent privacy, security, tax, payment, and legal review.
