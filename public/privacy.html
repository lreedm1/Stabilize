Privacy and memory

What the current prototype remembers

Guest use can retain bounded same-browser context, and signed-in use can retain separate cross-device context. Both modes use the retention, deletion, and provider-processing limits below.

Guest use

When you use Stabilize without signing in, a signed host-only cookie with a random identifier connects this browser profile to a bounded summary and up to eight recent messages stored by Stabilize on Cloudflare. Remembered text expires 30 days after the last committed exchange. The latest assistant reply and minimal display state may also be written to this browser's local storage. Records older than 30 days are ignored, and the app attempts to remove them on the next successful load. Browser or profile backups, unavailable JavaScript, or unavailable storage access may retain copies longer. The prompt and full transcript are not placed in that browser record, although a reply can reflect prompt details. Anyone sharing or copying this browser profile can share the guest context.

The random identifier can last up to one year and is not based on an IP address or fingerprint. Guest continuity resets at that absolute anniversary. Clearing cookies removes access but may leave an unreachable server record until its retention or cleanup deadline. Use Delete remembered conversation in the menu to erase live guest memory directly. Signing in does not move or merge guest memory; signing out resumes this browser's separate guest context.

Signed-in memory

Google sign-in is optional and associates a one-way account alias with a bounded summary and recent-message buffer stored by Stabilize on Cloudflare. That remembered text expires 30 days after the last committed exchange. You can also delete it from the signed-in account menu; signing out alone does not delete it. Signed-in assistant replies are not placed in the guest browser's latest-reply cache. After deletion succeeds, a signed, account-bound receipt cookie confirms the result on the next page and is then cleared; it contains no chat text. Cookies issued before the deletion are rejected from account features, so another browser or device using an older session must sign in again.

Public feedback

Signed-in users can optionally submit feedback. Each accepted submission is committed as a separate JSON file on the public feedback-inbox branch of the Stabilize GitHub repository. The committed record contains the feedback text, category, submission time, a random feedback identifier, and a note that the submission came from Stabilize. It does not include the Google account alias, email address, IP address, browser user agent, chat history, or payment information. Before a submission is accepted, the privacy-preserving account alias is temporarily used in a separate Durable Object to enforce the feedback rate limit; that rate-limit state is not included in the public feedback file. Because the Git repository is public, feedback submitters are told not to include private or identifying information and must acknowledge that warning before submission.

Paid model choice

If you subscribe to model choice, Stripe hosts checkout and the billing portal and processes payment information under Stripe's terms. Stabilize does not receive or store complete card numbers. It stores Stripe customer and subscription identifiers, subscription status, the chosen AI model, and a monthly paid-model message count under the same one-way account alias used for signed-in continuity. Billing records may remain longer than conversation memory because they are needed to provide and manage an active or historical subscription.

What is not used for memory

The application is not designed to use IP addresses as conversation-memory identifiers. It does not request your Google email for account memory. Infrastructure providers may still process network metadata under their own terms.

Third-party processing

Cloudflare hosts the application and handles requests. Google handles optional sign-in. GitHub stores optional public feedback. Stripe handles optional checkout, subscription billing, and the customer billing portal. OpenAI processes messages used to generate replies and condensed memory. Guest, summary, and signed-in reply requests use store: true, so OpenAI stores the resulting Response objects for at least 30 days unless organization or project data controls override the request. Stabilize does not retain those Response IDs, so Delete remembered conversation removes live Stabilize memory but cannot target the separately stored OpenAI objects. OpenAI may also retain data in abuse-monitoring logs under the deployment's applicable data controls and terms.

Use caution with sensitive information

Do not enter passwords, authentication codes, financial account numbers, or information you do not want transmitted to the service providers involved. No internet service can promise zero risk.

Prototype status: This summary describes the intended current implementation. A production launch requires independent privacy, security, tax, payment, and legal review.
