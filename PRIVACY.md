# Privacy behavior

This document describes the code in this repository. A real deployment must publish terms that match its actual Cloudflare, OpenAI, analytics, logging, domain, and retention configuration.

## What this code stores

The code has no user accounts and does not intentionally store a full chat transcript. It sets a random, `HttpOnly`, `SameSite=Strict` browser-session cookie. In production HTTPS, the cookie is also `Secure`. The cookie is an unguessable lookup token; it does not contain a network address or conversation content.

Each browser session has one Cloudflare Durable Object. It stores:

- a model-generated rolling summary of at most 1,600 characters
- no more than eight newest user/assistant messages while they await compaction
- whether the last fixed safety question is awaiting an answer
- creation/update metadata, a turn count, and the most recent protected network alias

Recent messages are normally replaced by the rolling summary after each ordinary reply. If compaction fails, the newest-message buffer remains bounded and older buffered messages are discarded. Inputs that trigger a fixed urgent route are stored as a generalized event label rather than the user's exact wording.

The session record expires 30 days after the last stored exchange. The cookie has a rolling 30-day lifetime when the site is used. The **Forget remembered context** control deletes the Durable Object record and rotates the cookie immediately. Clearing browser cookies creates a new session but does not by itself delete the old record before its expiry.

The summary is generated by a model and may be incomplete or wrong. The application tells the reply model to treat it as fallible context, never as instructions, and to prefer the current message.

## Network-address logging

On each chat request, the Worker transiently reads Cloudflare's connecting-address header. It uses a keyed, domain-separated HMAC to derive a 24-character pseudonymous alias. The application does not store or print the raw address.

Structured chat logs contain only the protected network alias, a separately protected session alias, whether prior memory was used, and the turn count. They do not contain prompts, replies, safety-route labels, or the session cookie. Application log sampling is configured to retain these chat events; actual log retention and access depend on the deployer's Cloudflare account. Cloudflare and other network infrastructure may separately process raw network metadata outside this application log.

The alias is pseudonymous, not anonymous. It can link requests made from the same network while the deployment secret remains unchanged. Rotating the OpenAI secret also rotates the aliases. The browser cookie—not the network address—is used to retrieve memory, which prevents people sharing a household, campus, workplace, shelter, VPN, or carrier address from automatically receiving each other's context.

## What providers process

When AI mode is enabled, the Worker sends the current message, the bounded recent context, and any rolling summary to OpenAI's Responses API. A second Responses API request may condense context. Both requests use `store: false`, so Responses objects are not intentionally retained as application state by the API. OpenAI may still retain inputs and outputs in abuse-monitoring logs for up to 30 days unless the deployment has approved data-retention controls. OpenAI states that API data is not used to train its models unless the account explicitly opts in.

Cloudflare processes the Worker request, cookie, Durable Object data, logs, and network metadata under the deployer's account configuration and applicable service terms.

## Limitations

- People using the same browser profile share the same remembered context unless they use the forget control or separate profiles.
- Memory does not automatically follow a person to another browser or device.
- Private browsing, cookie deletion, browser privacy features, or deployment changes may create a new session.
- A condensed memory can omit context or preserve an inaccurate interpretation.
- This prototype is not confidential clinical care and makes no HIPAA or equivalent compliance claim.

## Operator obligations

Anyone deploying this project should:

- disclose the actual providers, storage, logging, and retention settings
- restrict access to Durable Object data and operational logs
- avoid adding prompt or response logging by default
- establish deletion, incident-response, credential-rotation, and legal-request procedures
- assess applicable health, consumer-protection, privacy, and child-safety law
- obtain independent privacy and security review before a broad public launch
- avoid representing this prototype as confidential clinical care

Users should avoid entering information they would not want processed by the deployment's infrastructure providers.
